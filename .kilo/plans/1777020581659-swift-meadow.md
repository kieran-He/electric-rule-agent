# API流程与最新RAG系统对接分析

## 发现问题

**当前API流程并未完全使用最新的RAG改进**。

### 流程分析

1. **API调用链路**:
   ```
   QueryService.answer() 
   -> _get_orchestrator() 
   -> LangChainQAOrchestrator.run() (非HybridQAOrchestrator!)
   -> _retrieve() -> ChromaRepositoryRetriever (纯向量检索)
   ```

2. **配置检查**:
   - `.env`中配置了 `USE_LANGCHAIN=true` ✓
   - `.env`中配置了 `USE_HYBRID_RETRIEVAL=true` ✓
   - `.env`中配置了 `QUERY_REWRITE_ENABLED=true` ✓

3. **实际执行的流程**:
   - `QueryService._get_orchestrator()` 只检查 `use_langchain`：
   ```python
   if self.settings.use_langchain:
       return LangChainQAOrchestrator(db=db, settings=self.settings)
   else:
       return QAOrchestrator(db=db, settings=self.settings)
   ```
   - **没有检查 `use_hybrid_retrieval`**，所以返回的是 `LangChainQAOrchestrator`（纯向量检索）
   - **没有使用 `HybridQAOrchestrator`**（包含BM25 + BGE Rerank + Query Rewrite）

### 关键差距

| 功能 | 当前API流程 | HybridQAOrchestrator |
|------|-------------|----------------------|
| 检索方式 | 纯向量检索 | Vector + BM25混合 |
| Rerank | 无 | BGE-reranker-large |
| Query Rewrite | 无 | 启用并使用改进逻辑 |
| Query Expansion | 无 | 可配置 |

## 解决方案

### 方案A：修改QueryService（推荐）

修改 `app/services/query_service.py` 的 `_get_orchestrator()` 方法：

**当前代码**（第18-24行）:
```python
def _get_orchestrator(self, db: Session):
    """Get orchestrator based on USE_LANGCHAIN flag."""
    if self.settings.use_langchain:
        from app.langchain.orchestrator import LangChainQAOrchestrator
        return LangChainQAOrchestrator(db=db, settings=self.settings)
    else:
        return QAOrchestrator(db=db, settings=self.settings)
```

**修改为**:
```python
def _get_orchestrator(self, db: Session):
    """Get orchestrator based on USE_LANGCHAIN and USE_HYBRID_RETRIEVAL flags."""
    if self.settings.use_langchain:
        if self.settings.use_hybrid_retrieval:
            from app.langchain.orchestrator_hybrid import HybridQAOrchestrator
            return HybridQAOrchestrator(db=db, settings=self.settings)
        else:
            from app.langchain.orchestrator import LangChainQAOrchestrator
            return LangChainQAOrchestrator(db=db, settings=self.settings)
    else:
        from app.services.qa.orchestrator import QAOrchestrator
        return QAOrchestrator(db=db, settings=self.settings)
```

**改动说明**:
- 新增检查 `use_hybrid_retrieval` 配置
- 如果同时启用 `use_langchain` 和 `use_hybrid_retrieval`，返回 `HybridQAOrchestrator`
- 向后兼容：只启用 `use_langchain` 时仍返回 `LangChainQAOrchestrator`

### 方案B：添加环境变量开关（不推荐）

新增环境变量 `USE_HYBRID_ORCHESTRATOR=true`，但这会增加配置复杂度。

## 修改后的效果

### API将使用的完整RAG流程

```
QueryService.answer()
-> HybridQAOrchestrator.run()
-> _retrieve() -> HybridRetriever.retrieve()
   -> QueryRewriter.rewrite() (query rewrite enabled)
   -> Vector检索 + BM25检索
   -> BGEReranker.rerank(rerank_query) (使用重写query)
-> _generate_answer() -> MiniMaxLLM
```

### 关键改进点激活

1. **Query Rewrite**: 
   - 触发条件：`query_rewrite_enabled=true`（已配置）
   - 效果：口语化query → 正式政策术语

2. **改进的Rerank逻辑**:
   - 触发条件：启用query rewrite后，`HybridRetriever` 使用 `queries[-1]`（重写query）进行rerank
   - 位置：`hybrid_retriever.py:230`
   - 效果：Top Score +0.0119, Recall +0.0333

## 结论

**当前API测试并未使用最新的RAG流程**，因为 `QueryService` 没有根据 `use_hybrid_retrieval` 配置选择正确的 `Orchestrator`。

需要修改 `app/services/query_service.py` 的 `_get_orchestrator()` 方法，使其能够根据配置选择 `HybridQAOrchestrator`。
