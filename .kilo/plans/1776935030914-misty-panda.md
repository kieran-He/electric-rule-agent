## 关键决策点详解

### 决策1: 知识库省份列表来源

**用户问题**: "如果用户问之前不知道哪个省份怎么办"

**解答**: 这个决策是关于**系统如何知道支持哪些省份**，不是关于用户如何指定省份。

**场景举例**:
```
用户问: "山东省电力市场规则是什么？"
系统识别: 省份=山东(SD)
问题: 系统需要知道"知识库有没有山东省的文档"

选项A（静态配置）:
  - 在配置文件写: supported_provinces = ["SN"]  # 只有陕西
  - 缺点: 添加新省份文档时，需要手动改配置

选项B（动态查询）:
  - 启动时查询ChromaDB: 有哪些collection？["kb_sn", "kb_global"]
  - 自动识别: 支持省份=["SN"]
  - 优点: 添加新省份文档后，系统自动识别
```

**用户不指定省份的处理**（已有实现，见service.py第115-130行）:
```python
# 如果用户问: "电力市场交易流程是什么？"（不指定省份）
if not provinces:  # 没识别到省份
    # 系统回复: "请先确认省份，例如：陕西、广东、山东。"
    response = QueryResponse(
        needs_confirmation=True,
        confirmation_question="请先确认省份...",
        follow_up="请补充省份后重试..."
    )
    return response
```

**建议**: 选项B（动态查询），更智能，减少维护成本

### 决策2: 领域关键词检查方式

**用户问题**: "这个检查如果没通过会怎样，是如何检查的"

**解答**: 

**检查逻辑**:
```python
POWER_DOMAIN_KEYWORDS = ["电力", "市场", "交易", "现货", "中长期", "结算", "储能", "发电", "售电"]

def is_power_domain_query(query: str) -> bool:
    """检查问题是否涉及电力市场领域"""
    return any(keyword in query for keyword in POWER_DOMAIN_KEYWORDS)

# 举例:
# "中国股市最新政策" → 不包含电力关键词 → False → 拒绝
# "电力市场交易流程" → 包含"电力"、"市场"、"交易" → True → 继续
```

**检查不通过的后果**:
```python
if not is_power_domain_query(req.query):
    # 完全不相关领域（如"中国股市政策"）
    response = QueryResponse(
        conclusion="抱歉，我专注于电力市场政策咨询，无法回答股市相关问题。",
        follow_up="请咨询电力市场相关问题..."
    )
    return response  # 直接拒绝，不检索任何文档
```

**选项对比**:

| 方式 | 检查过程 | 成本 | 延迟 |
|------|----------|------|------|
| 硬编码关键词 | 检查query是否包含电力关键词 | 0 | <1ms |
| LLM判断 | 调用LLM判断"这是电力市场问题吗？" | 高 | ~1s |

**建议**: 选项A（硬编码关键词），快速低成本，覆盖95%场景

### 决策3: 省份检查逻辑位置

**用户问题**: "啥是service层"

**解答**: 

**代码架构分层**:
```
┌─────────────────────────────────────────┐
│ 用户问题: "山东省电力市场规则是什么？"   │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│ Service层 (app/service.py)              │ ← 业务逻辑层
│ - 接收用户请求                           │
│ - 识别省份（山东=SD）                    │
│ - 检查省份是否支持 ❌                     │ ← 省份检查在这里
│ - 决策: reject / retrieve                │
└─────────────────────────────────────────┘
              ↓ (如果省份支持)
┌─────────────────────────────────────────┐
│ Retriever层 (app/langchain/hybrid_retriever.py) │ ← 检索逻辑层
│ - Vector检索                             │
│ - BM25检索                               │
│ - Rerank重排序                           │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│ Repository层 (app/repository.py)        │ ← 数据访问层
│ - ChromaDB查询                           │
│ - 返回文档chunks                         │
└─────────────────────────────────────────┘
```

**为什么放在Service层**:
- Service层是"大脑"，负责决策（该不该检索）
- Retriever层是"手脚"，负责执行（如何检索）
- 省份检查是决策，应该在"大脑"层

**举例**:
```python
# Service层 (app/service.py) - 决策层
class PolicyQueryService:
    def process(self, req: QueryRequest):
        detection = detector.detect(req.query)  # 识别省份
        
        if detection.province_code not in supported_provinces:  # 检查支持
            return QueryResponse(conclusion="不支持该省份")  # 直接拒绝
        
        chunks = retriever.retrieve(query, provinces)  # 调用检索层
        ...

# Retriever层 - 执行层
class HybridRetriever:
    def retrieve(self, query, provinces):
        # 只负责检索，不负责决策
        vector_chunks = repo.retrieve(...)
        bm25_chunks = bm25.search(...)
        reranked = reranker.rerank(...)
        return reranked
```

**建议**: Service层（决策层），符合职责分离原则

def get_supported_provinces(repo: ChromaPolicyRepository) -> List[str]:
    """启动时动态查询支持的省份"""
    collections = repo._client.list_collections()

```python
class HybridRetriever:
    def __init__(self, ...):
        ...
        self._supported_provinces = None  # 缓存支持省份列表
    
    def _get_supported_provinces(self) -> List[str]:
        """动态获取支持的省份列表"""
        if self._supported_provinces is None:
            collections = self.vector_repo._client.list_collections()
            self._supported_provinces = [
                c.name.replace("kb_", "").upper() 
                for c in collections 
                if c.name.startswith("kb_") and c.name != "kb_global"
            ]
        return self._supported_provinces
    
    def retrieve(self, query: str, province_codes: List[str]) -> List[PolicyChunk]:
        """
        检索流程（包含省份检查）
        
        Returns:
            如果省份不支持，返回空列表 [] 表示拒绝
        """
        # 新增：省份支持检查
        supported = self._get_supported_provinces()
        for province_code in province_codes:
            if province_code not in supported:
                logger.info(f"Province {province_code} not supported (supported: {supported})")
                return []  # 返回空列表表示拒绝
        
        # 原有的检索逻辑
        queries = self._expand_query(query)
        ...
```

**架构调整**:
```

Retriever层 (hybrid_retriever.py): ← 省份检查在这里
  - 省份检查: SD in supported_provinces? ❌
  - 返回: [] (拒绝)

Repository层 (repository.py):
  - ChromaDB查询（如果省份支持才执行）
```
