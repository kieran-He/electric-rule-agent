# Query Rewrite & Expansion 改进计划

## 目标

1. **Query Rewrite**: 强制每次触发，由 LLM 执行重写
2. **Query Expansion**: 基于 LLM 的语义拆分，支持：
   - 多省份拆分：如 "陕西和山东现货市场" → ["陕西现货市场", "山东现货市场"]
   - 多市场类型拆分：如 "陕西中长期和现货市场" → ["陕西中长期市场", "陕西现货市场"]

### 2. Query Rewrite 强制触发

**文件**: `app/langchain/query_rewriter.py`

修改点：
- 移除 `should_rewrite` 条件判断逻辑
- `rewrite()` 方法强制调用 LLM
- 简化 prompt 以减少延迟

新的 System Prompt：
```python
SYSTEM_PROMPT = """你是电力政策检索专家。将用户查询改写为更精确的检索形式。

规则：
1. 补充领域关键词（如"交易规则" → "交易实施细则"）
2. 去除口语化表达
3. 添加必要限定词

输出JSON：{"rewritten": "改写后的查询"}"""
```

### 3. Query Expansion 语义拆分

**文件**: `app/langchain/query_expander.py`

新增方法：
- `expand_semantic(query)` - LLM 语义拆分
- 新增配置项支持 LLM wrapper 传入

System Prompt 设计：
```python
SEMANTIC_SPLIT_PROMPT = """你是电力政策检索专家。分析用户查询，拆分为多个独立查询。

拆分规则：
1. 多省份：如"陕西和山东现货市场"拆为["陕西现货市场规则", "山东现货市场规则"]
2. 多市场：如"中长期和现货市场"拆为["中长期市场规则", "现货市场规则"]
3. 复合条件：拆分每个独立查询

输出JSON：{"split_queries": ["查询1", "查询2", ...], "reason": "拆分原因"}"""
```

### 4. HybridRetriever 调用顺序调整

**文件**: `app/langchain/hybrid_retriever.py`

当前流程：
```
query → rewrite → expand → retrieve
```

新流程：
```
query → rewrite(LLM强制) → expand(LLM语义拆分) → retrieve
```

修改 `_expand_queries` 支持语义拆分方法。

### 5. 配置文件更新

**文件**: `app/config.py`

新增配置项：
```python
llm_timeout_seconds: int = int(_env("LLM_TIMEOUT_SECONDS", "120"))
query_expansion_method: str = _env("QUERY_EXPANSION_METHOD", "semantic")  # 改为 semantic

```

## 性能考虑

- LLM 强制调用会增加延迟约 2-5 秒
- 可能需要增加 max_workers 或优化并发
- 建议启用 query_rewrite_keep_original 保留原查询作为备选

## 测试用例

1. "陕西省电力现货市场的交易规则" → LLM 重写 + 无拆分
2. "陕西和山东现货市场规则" → 拆分为两个查询
3. "中长期和现货市场交易流程" → 拆分为两个查询
4. "怎么参与现货市场" → LLM 重写为精确查询
