# 飞书机器人重复回复问题修复方案

## 问题分析

### 当前去重逻辑

**位置**: `app/services/feishu_bot_service.py:32-48`

```python
self._processed_messages: deque = deque(maxlen=1000)
self._processed_ttl = 300  # 5分钟
```

**工作原理**:
1. 使用内存中的 `deque` 存储已处理的消息 ID 和时间戳
2. 每次处理消息前调用 `_check_and_mark()` 检查是否重复
3. 自动清理超过 300 秒的旧记录

### 问题原因

**飞书事件重试机制**: 飞书 WebSocket 长连接在消息推送后，如果应用处理时间过长或连接不稳定，飞书可能会在几分钟后重发同一条消息。重试间隔可能是 1分钟、5分钟、10分钟等逐渐增加。

**当前方案的缺陷**:
1. **内存存储**: 服务重启后记录丢失
2. **TTL 不够长**: 300 秒（5分钟）可能不足以覆盖飞书重试的最大时间窗口
3. **多实例不共享**: 如果部署多个实例，无法共享去重记录

## 修复方案

### 方案 A: 延长 TTL + 数据库持久化（推荐）

使用 SQLite/数据库存储已处理消息，支持持久化和多实例共享。

**修改文件**: `app/services/feishu_bot_service.py`

#### 1. 添加数据库模型

创建 `app/models/processed_message.py`:

```python
from datetime import datetime
from sqlalchemy import Column, String, DateTime, Index
from app.db.base import Base

class ProcessedMessage(Base):
    __tablename__ = "processed_messages"
    
    message_id = Column(String(64), primary_key=True)
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False)
    
    __table_args__ = (
        Index('ix_processed_messages_created_at', 'created_at'),
    )
```

#### 2. 修改 FeishuBotService

```python
from datetime import datetime, timedelta
from app.models.processed_message import ProcessedMessage

class FeishuBotService:
    def __init__(self, ...):
        ...
        self._processed_ttl = 3600  # 延长到 1 小时

    def _check_and_mark(self, message_id: str) -> bool:
        with self.session_factory() as session:
            # 检查是否已存在
            existing = session.query(ProcessedMessage).filter(
                ProcessedMessage.message_id == message_id
            ).first()
            if existing:
                return True
            
            # 清理过期记录
            cutoff = datetime.utcnow() - timedelta(seconds=self._processed_ttl)
            session.query(ProcessedMessage).filter(
                ProcessedMessage.created_at < cutoff
            ).delete()
            
            # 标记为已处理
            session.add(ProcessedMessage(message_id=message_id))
            session.commit()
            return False
```

#### 3. 添加数据库迁移

在 `init_db()` 中自动创建表。

### 方案 B: 简化方案 - 仅延长 TTL

如果不想引入数据库，可以简单延长内存 TTL：

```python
self._processed_ttl = 3600  # 从 300 改为 3600（1小时）
```

**优点**: 最小改动
**缺点**: 服务重启后仍可能重复回复

## 推荐

采用 **方案 A**，因为：
1. 项目已有 SQLite 数据库，改动成本低
2. 支持服务重启后不丢失记录
3. 支持多实例部署

### 步骤 3: 修改 FeishuBotService

**修改文件**: `app/services/feishu_bot_service.py`

1. 删除内存去重相关代码（`_processed_messages`, `_processed_ttl`, `_lock`, `_check_and_mark`）
2. 添加数据库去重方法：

```python
from datetime import datetime, timedelta
from app.db.models.processed_message import ProcessedMessage

class FeishuBotService:
    def __init__(self, ...):
        ...
        self._processed_ttl = 3600  # 1 小时

    def _check_and_mark(self, message_id: str) -> bool:
        with self.session_factory() as session:
            try:
                existing = session.query(ProcessedMessage).filter(
                    ProcessedMessage.message_id == message_id
                ).first()
                if existing:
                    return True
                
                cutoff = datetime.utcnow() - timedelta(seconds=self._processed_ttl)
                session.query(ProcessedMessage).filter(
                    ProcessedMessage.created_at < cutoff
                ).delete()
                
                session.add(ProcessedMessage(message_id=message_id))
                session.commit()
                return False
            except Exception:
                session.rollback()
                raise
```

### 步骤 4: 数据库迁移

服务启动时会自动创建新表（`Base.metadata.create_all`）。
