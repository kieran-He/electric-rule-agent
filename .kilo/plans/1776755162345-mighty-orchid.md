## 当前架构深度分析（2026-04-23）

### 架构模式识别

**当前架构：简单Orchestrator模式**（非Agent架构）

```
用户查询 → QAOrchestrator.run()
         ↓
         _retrieve()      [固定检索，每次都执行]
         ↓
         _generate_answer() [固定生成，每次都执行]
         ↓
         返回QueryAnswer
```

### 架构特点分析

| 特性 | 当前实现 | 评估 |
|------|---------|------|
| **流程模式** | 固定线性流程 | ✅ 简单可靠，❌ 不够灵活 |
| **检索决策** | 无决策逻辑（每次都检索） | ❌ 无LLM决策能力 |
| **工具系统** | 无工具调用机制 | ❌ 不支持多工具 |
| **多轮对话** | history参数存在但未使用（第87行空列表） | ❌ 无对话记忆 |
| **状态管理** | 无状态持久化 | ❌ 每次查询独立 |
| **跨省对比** | 简单合并多省结果 | ⚠️ 逻辑固定，无动态对比 |

### 核心组件关系图

```
FastAPI Router (routes_query.py)
         ↓
QueryService.answer()
         ↓
QAOrchestrator.run()
    ├─ ChromaPolicyRepository.retrieve()
    ├─ LLMClient.generate_answer()
    └─ 返回QueryAnswer
```

**依赖关系**：
- `QAOrchestrator` → `ChromaPolicyRepository` (检索)
- `QAOrchestrator` → `LLMClient` (生成)
- 无中间决策层

## LangChain整合方案设计

### 整合范围决策：部分整合 + Agent架构预留

**整合策略**：渐进式整合，先解决关键问题，再扩展架构能力

| 组件 | 整合决策 | 原因 | 风险 |
|------|---------|------|------|
| **Ragas LLM** | ✅ 必须整合 | 解决Anthropic兼容性问题 | 低 |
| **LLM Client** | ✅ 必须整合 | 统一LLM接口，支持后续Agent | 低 |
| **Retriever** | ⚠️ 暂时保留 | ChromaPolicyRepository已优化，数据稳定 | 低 |
| **Orchestrator** | ⚠️ 重构为LCEL chain + Agent预留接口 | 标准化流程，预留扩展能力 | 中 |
| **Embeddings** | ⚠️ 暂时保留 | DeterministicEmbedder稳定，无需改动 | 低 |

```python
from langchain_anthropic import ChatAnthropic
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough, RunnableLambda

# 1. LLM组件
def create_minimax_llm():
    return ChatAnthropic(
        model="MiniMax-M2.7",
        api_key=os.getenv("LLM_API_KEY"),
        anthropic_api_url=os.getenv("LLM_ENDPOINT"),
        max_tokens=2048,
    )

# 2. Retriever包装器（保留现有ChromaPolicyRepository）
class ChromaRepositoryRetriever:
    """将ChromaPolicyRepository包装为LangChain Retriever"""
    def __init__(self, repo: ChromaPolicyRepository, province_codes: list[str], top_k: int):
        self.repo = repo
        self.province_codes = province_codes
        self.top_k = top_k
    
    def __call__(self, query: str) -> list[PolicyChunk]:
        return self.repo.retrieve(query, self.top_k, "province", self.province_codes[0])

# 3. Prompt模板
QA_PROMPT = ChatPromptTemplate.from_messages([
    ("system", "你是电力政策问答助手。只能根据提供的证据回答，禁止编造。如果证据不足，明确说明\"未检索到充分依据\"。"),
    ("human", """问题: {question}

省级证据({province_code}):
{context}

历史对话:
{history}"""),
])

# 4. LCEL Chain构建
def build_qa_chain(llm, retriever):
    def format_context(chunks):
        lines = []
        for i, chunk in enumerate(chunks, 1):
            source = chunk.metadata.get("source_name", "unknown")
            lines.append(f"{i}. [{source}] {chunk.text[:260]}")
        return "\n".join(lines)
    
    chain = (
        {
            "question": RunnablePassthrough(),
            "context": retriever | RunnableLambda(format_context),
            "province_code": RunnablePassthrough(),
            "history": RunnableLambda(lambda x: ""),  # 预留对话记忆
        }
        | QA_PROMPT
        | llm
        | StrOutputParser()
    )
    return chain

# 5. Agent预留接口（未来扩展）
class LangChainQAOrchestrator:
    """支持未来扩展为Agent的Orchestrator"""
    def __init__(self, db: Session, use_agent: bool = False):
        self.llm = create_minimax_llm()
        
        if use_agent:
            # 未来：切换为Agent模式
            self.chain = self._build_agent()
        else:
            # 当前：Chain模式
            self.chain = self._build_chain()
    
    def _build_chain(self):
        retriever = ChromaRepositoryRetriever(...)
        return build_qa_chain(self.llm, retriever)
    
    def _build_agent(self):
        # 未来：实现Agent模式
        # from langchain.agents import create_structured_chat_agent
        # tools = [RetrieverTool(), CalculatorTool(), ...]
        # return create_structured_chat_agent(self.llm, tools, ...)
        pass
    
    def run(self, req: QueryRequest) -> QueryAnswer:
        answer = self.chain.invoke(req.query)
        # 构建citations...
        return QueryAnswer(...)
```

**优点**：
- ✅ 解决Ragas兼容性问题（使用LangchainLLMWrapper）
- ✅ 统一LLM接口（ChatAnthropic）
- ✅ 标准化流程（LCEL chain）

- ✅ 支持流式输出（未来启用）

## 延迟来源深度分析

### 实测延迟对比

| 测试场景 | 响应时间 | 备注 |
|---------|---------|------|
| MiniMax API（纯请求） | 0.3秒 | 无thinking参数 |
| 实际RAG系统 | 38秒 | 包含thinking + 检索 + 处理 |

**延迟分解（38秒）**:
1. ChromaDB检索: ~5-10秒
2. Embedding计算（cached）: ~1-2秒
3. Prompt构建: ~1秒
4. **MiniMax API（含thinking）**: **~25秒** ← 主要延迟源
5. 响应处理: ~1秒

### Thinking块延迟影响

**假设**: MiniMax默认启用extended thinking（类似Claude）
- thinking过程消耗大量时间（生成思考链）
- thinking块内容较长（可能数千字符）
- 当前实现忽略thinking块，但API仍生成

**验证方法**:
```python
# 修改generator.py打印所有块类型和长度
for block in content_blocks:
```

#### Step 2: 重写generator.py使用Anthropic SDK
```python
# app/generator.py
import anthropic

class LLMClient:
    def __init__(self, api_key: str, endpoint: str, model: str, timeout_seconds: int = 30):
        self.client = anthropic.Anthropic(
            api_key=api_key,
            base_url=endpoint,
        )
        self.model = model
        self.timeout_seconds = timeout_seconds
    
    def _call_anthropic_sdk(self, system: str, user_content: str) -> str:
        """使用Anthropic SDK调用API"""
        message = self.client.messages.create(
            model=self.model,
            max_tokens=2048,
            system=system,
            messages=[{"role": "user", "content": user_content}],
        )
        
        # 只提取text块，忽略thinking块
        text_content = ""
        for block in message.content:
            if block.type == "text":
                text_content += block.text
        
        return text_content.strip()
    
    def generate_answer(self, query, chunks, ...):
        system = self._build_system_prompt()
        user_content = f"问题: {query}\n\n证据:\n{self._build_context(chunks)}"
        return self._call_anthropic_sdk(system, user_content)
```

**优点**:
- SDK自动处理thinking参数
- 更简洁的代码
- SDK可能有性能优化

**缺点**:
- 新依赖（anthropic包）
- 需要重写现有代码
