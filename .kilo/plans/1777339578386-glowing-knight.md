# 飞书机器人流程加速优化计划

## 问题分析

### 当前流程耗时分析（基于日志）

| 阶段 | 时间戳 | 耗时 | 问题 |
|------|--------|------|------|
| 收到消息 | 02:02:58 | - | 开始 |
| 发送临时回复 | 02:03:01 | **3秒** | 过长，应立即回复 |
| 加载 Embedding 模型 | 02:03:01-02:03:11 | **~10秒** | 每次请求重新加载 |
| 加载 Reranker 模型 | 02:03:12-02:03:20 | **~8秒** | 每次请求重新加载 |
| LLM 生成 | 02:04:04-02:04:13 | **~54秒** | 两次 API 调用 |
| **总耗时** | - | **~75秒** | 用户等待过长 |

### 根本原因

1. **Embedding 模型无缓存**：`ChromaPolicyRepository.__init__()` 每次创建都加载 `SentenceTransformer`
2. **HybridQAOrchestrator 每次重建**：`QueryService.answer()` 每次创建新 orchestrator
3. **模型加载时机错误**：收到消息后才加载，而非启动时预热
4. **缺少 trace_id**：日志无法关联同一请求的所有操作

### 代码调用链

```
FeishuBotService.handle_message()
    → QueryService.answer()               # 每次创建新实例
        → HybridQAOrchestrator(db, settings)  # 每次创建新实例
            → ChromaPolicyRepository(...)     # 加载 Embedding (~10s)
            → BM25Indexer.build_index()       # 构建索引
            → preload_reranker()              # 加载 Reranker (~8s)
```

## 优化方案

### 1. 创建 Embedding 模型缓存（类似 RerankerCache）

**新建文件**: `app/core/embedding_cache.py`

```python
class EmbeddingCache:
    _instance = None
    _lock = threading.Lock()
    
    def preload(self, model_name: str) -> SentenceTransformer:
        # 单例模式，只加载一次
    
embedding_cache = EmbeddingCache()
```

### 2. 修改 ChromaPolicyRepository 使用缓存

**修改文件**: `app/core/repository.py`

- 将 `SentenceTransformer(model_name)` 改为从 `embedding_cache` 获取
- 避免每次实例化都重新加载模型

### 3. 创建 HybridQAOrchestrator 单例

**新建文件**: `app/services/orchestrator_singleton.py`

```python
class OrchestratorSingleton:
    _instance = None
    _lock = threading.Lock()
    
    def get_or_create(self, db, settings) -> HybridQAOrchestrator:
        # 单例模式，只初始化一次
        # 注意：db 参数需要每次传入（Session 不能复用）
```

### 4. 修改 QueryService 使用单例

**修改文件**: `app/services/query_service.py`

- 将 orchestrator 改为单例获取
- 避免 `answer()` 每次创建新 orchestrator

### 5. 启动时预热模型

**修改文件**: `app/feishu_bot.py`

在 `FeishuBot.start()` 中：

```python
def start(self):
    self._init_db()
    self._init_client()
    
    # 预热模型（启动时加载，而非请求时）
    self._preload_models()
    
    # ... WebSocket 启动 ...

def _preload_models(self):
    from app.core.embedding_cache import embedding_cache
    from app.langchain.reranker_cache import reranker_cache
    
    logger.info("Preloading embedding model...")
    embedding_cache.preload(settings.embedding_model)
    
    logger.info("Preloading reranker model...")
    reranker_cache.preload(settings.reranker_model, settings.reranker_max_length)
    
    logger.info("Preloading HybridQAOrchestrator...")
    # 初始化 orchestrator 单例（预热 BM25 等）
    
    logger.info("All models preloaded successfully")
```

### 6. 添加 trace_id 支持

**修改文件**: `app/services/feishu_bot_service.py`

在 `handle_message()` 开头：

```python
def handle_message(self, data):
    trace_id = f"trace_{uuid.uuid4().hex[:12]}"
    from app.core.logging_context import set_trace_id, set_session_id
    set_trace_id(trace_id)
    set_session_id(session_id)
    logger.info(f"Received message: {text[:100]}")
    # ...
```

## 预期优化效果

| 阶段 | 当前耗时 | 优化后耗时 | 说明 |
|------|----------|-----------|------|
| 临时回复 | 3秒 | <1秒 | 立即回复 |
| Embedding 加载 | 10秒 | 0秒 | 启动时预热 |
| Reranker 加载 | 8秒 | 0秒 | 启动时预热 |
| BM25 构建 | ~2秒 | 0秒 | 启动时预热 |
| 检索+Rerank | ~1秒 | ~1秒 | 无变化 |
| LLM 生成 | 54秒 | 54秒 | 无变化（取决于 API） |
| **总耗时** | **~75秒** | **~56秒** | 减少 ~19秒 |

### 用户体验改善

- 发送消息后 **1秒内** 收到"正在思考中..."
- 实际答案在 **~56秒** 内返回（vs 当前 ~75秒）
- 启动时预热约 **30秒**（一次性，后台完成）

## 注意事项

1. **Session 不能复用**：`HybridQAOrchestrator` 的 `db` 参数每次请求需要新 Session
2. **线程安全**：所有缓存使用 `threading.Lock` 保证线程安全
3. **内存占用**：预热后模型常驻内存，约 2-3GB
4. **测试验证**：修改后运行 `pytest tests/` 确保功能正确
