# 改进Rerank阶段使用重写Query的计划

## 问题分析

当前实现在hybrid_retriever.py第230行：
```python
final_chunks = self.reranker.rerank(query, all_candidates, top_k=self.final_top_k)
```

**核心问题**：虽然检索阶段使用了多个query（原query + 重写query），但rerank阶段只用原query进行排序，导致：
1. 检索候选集可能因重写query略有扩大
2. 但最终排序由原query决定，削弱了query重写的效果
3. 从测试结果看，10条query的检索结果完全相同，无实质差异

## 改进方案对比

### 方案1：优先使用重写query进行rerank（推荐）
- **实现**：用queries列表的最后一个query进行rerank
- **逻辑**：
  - 如果触发重写且keep_original=True → queries=[原query, 重写query] → 用重写query rerank
  - 如果触发重写且keep_original=False → queries=[重写query] → 用重写query rerank  
  - 如果未触发重写 → queries=[原query] → 用原query rerank
- **优点**：
  - 改动最小，只需修改1行代码
  - 重写query更精确，理论上rerank效果更好
  - 保持检索阶段的双query策略（扩大候选集）
- **缺点**：
  - 可能丢失原query的一些意图
- **适用场景**：当前配置keep_original=True，适合此方案

### 方案2：双rerank策略
- **实现**：分别用原query和重写query进行rerank，取score最高的结果
- **逻辑**：
  - if len(queries) > 1:
    - rerank_result1 = reranker.rerank(queries[0], all_candidates)
    - rerank_result2 = reranker.rerank(queries[1], all_candidates)
    - 选择top_score更高的结果
  - else:
    - 正常rerank
- **优点**：
  - 双保险，保留两种query的优势
  - 可以动态选择最佳rerank策略
- **缺点**：
  - 计算成本增加2倍（rerank是最慢的步骤）
  - 需要更多代码改动
- **适用场景**：对效果要求极高，可接受性能损失

### 方案3：智能选择策略
- **实现**：根据rewrite confidence决定用哪个query
- **逻辑**：
  - if confidence > 0.8: 用重写query rerank
  - else: 用原query rerank
- **优点**：
  - 更智能，自适应
- **缺点**：
  - 需要从RewriteResult传递confidence信息
  - 逻辑复杂度增加

## 推荐方案：方案1（优先使用重写query）

**理由**：
1. 改动最小，风险最低
2. 重写query设计目标就是更精确，适合rerank
3. 检索阶段仍保留双query策略（扩大候选集）
4. 测试验证简单，只需对比before/after

## 补充说明

### 为什么queries[-1]是重写query？

**queries列表的形成过程**（hybrid_retriever.py第207-208行）：
```python
queries = self._rewrite_query(query)        # 第207行
queries = self._expand_queries(queries)     # 第208行
```

**_rewrite_query方法返回逻辑**（第241-268行）：
```python
if result.triggered:
    if self.query_rewrite_keep_original:
        return [query, result.rewritten_query]  # [原query, 重写query]
    else:
        return [result.rewritten_query]         # [重写query]
else:
    return [query]                              # [原query]
```

**结论**：
- queries[-1]（最后一个元素）总是最精确的query
- 触发重写时 → queries[-1] = 重写query
- 未触发重写 → queries[-1] = 原query
- **这是设计的必然结果**，不是巧合

### 配置影响

**当前配置**（app/config.py第52-54行）：
```python
query_rewrite_enabled: bool = False  # 默认关闭
query_rewrite_keep_original: bool = True  # 保留原query
```

**影响分析**：
1. **query_rewrite_enabled=False**：
   - queries始终=[原query]
   - rerank_query=queries[-1]=原query
   - **行为与原来完全一致**（向后兼容）
   
2. **query_rewrite_enabled=True, keep_original=True**（推荐配置）：
   - 触发重写 → queries=[原query, 重写query]
   - rerank_query=queries[-1]=重写query
   - **启用新特性，用重写query rerank**
   
3. **query_rewrite_enabled=True, keep_original=False**：
   - 触发重写 → queries=[重写query]
   - rerank_query=queries[-1]=重写query
   - **全流程只用重写query**
