# 飞书机器人接入方案

## 需求确认

- **机器人类型**：应用机器人（已创建）
- **使用场景**：用户问答交互
- **会话场景**：私聊 + 群聊
- **回复方式**：流式回复
- **实施方式**：分步实施（先基础接入，后流式回复）

## 现有实现分析

已有 `app/feishu_bot_test.py` 基础流程：
- 使用 `lark_oapi` SDK（官方 Python SDK）
- **WebSocket 长连接**接收事件（非 HTTP webhook）
- 已注册 `P2ImMessageReceiveV1` 事件处理器
- 已实现消息回复 `ReplyMessageRequest`

**WebSocket 方式优势**：
- 无需公网可访问的服务器
- 无需配置回调 URL 和签名验证
- 无需处理加密解密
- 实现更简单

**注意事项**：
- 需保持 WebSocket 长连接稳定
- 需处理连接断开重连逻辑

## 需要获取的凭证

从飞书开放平台获取：
| 信息 | 用途 | 位置 |
|------|------|------|
| `App ID` | 应用标识 | 应用详情 → 凭证与基础信息 |
| `App Secret` | 认证 | 应用详情 → 凭证与基础信息 |

**权限要求**（需确认已申请）：
- `im:message` - 获取消息
- `im:message:send_as_bot` - 以机器人身份发消息
- `im:message:p2p` - 获取私聊消息
- `im:chat` - 获取群信息

## 分步实施计划

### 第一阶段：基础问答接入（基于现有代码）

**目标**：用户在飞书中提问，机器人调用 QueryService 返回答案

**开发任务**：
1. **集成 QueryService**
   - 创建 `app/services/feishu_bot_service.py`
   - 在消息处理中调用 `QueryService.answer()`
   - 管理 session_id 与 open_id 的关联

2. **扩展消息处理**
   - 提取消息文本内容（去除@部分）
   - 区分私聊和群聊场景
   - 构建查询请求 `QueryRequest`

3. **优化回复内容**
   - 支持 Markdown 格式（飞书支持）
   - 显示引用来源

**产出文件**：
```
app/
├── services/
│   └── feishu_bot_service.py   # 新增：消息处理、调用 QueryService
├── feishu_bot.py               # 新增：正式版机器人（基于 feishu_bot_test.py）
├── config.py                   # 扩展：增加飞书配置项
```

### 第二阶段：流式回复

**目标**：答案逐步显示，用户体验更好

**开发任务**：
1. 实现流式消息内容更新
2. 显示"正在思考..."状态
3. 分段更新答案内容

**技术方案**：
- 使用飞书"流式消息"API（`/im/v1/messages/:message_id/update`）
- 或使用卡片消息动态更新
