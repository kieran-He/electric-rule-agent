# 上下文记忆管理优化方案

## 当前实现分析

### 现有架构
```
ConversationState 表:
- session_id (唯一标识)
- province_code, market_type, entity_type (槽位信息)
- last_question (仅最后一轮问题)
- last_intent (最后意图)
- updated_at (更新时间)
```

### 核心问题
1. **历史不完整**: `get_history()` 只返回 `last_question`，无法重建完整对话
2. **Bot回复丢失**: `append_turn()` 不存储 `bot_reply`，无法形成 Q&A 对
3. **无多轮累积**: 只保存最后一轮，之前对话全部丢失
4. **数据库频繁访问**: 每次请求都读写数据库

### 方案 3: 历史摘要（LLM 压缩长对话）

**实现方式**:
```python
class HistorySummarizer:
    def summarize(history: list[dict], max_tokens: int = 200) -> str:
        if len(history) <= 4:
            return format_history(history)
        
        # 调用 LLM 生成摘要
        prompt = f"请将以下对话历史压缩为不超过{max_tokens}字的摘要：\n{format_history(history)}"
        return llm.invoke(prompt)
    
    def get_context_for_query(session_id, current_query) -> str:
        history = get_history(session_id)
        summary = summarize(history[:-2])  # 保留最近2轮，压缩历史
        return f"历史摘要: {summary}\n\n最近对话: {format_history(history[-2:])}"
```

**收益**:
- ✅ 支持超长对话（>10轮）
- ✅ 大幅减少 token 消耗
- ✅ 保留核心信息，过滤冗余
- ✅ 提升模型理解效率

**付出**:
- ❌ 额外 LLM 调用（+500ms 延迟）
- ❌ 增加 API 成本（每次摘要）
- ❌ 摘要可能丢失关键细节
- ❌ 摘要质量依赖 LLM 能力

**推荐指数**: ⭐⭐⭐（可选，长对话场景推荐）

### 方案 5: 向量检索历史（相关性过滤）

**实现方式**:
```python
class HistoryRetriever:
    def get_relevant_history(session_id, current_query, top_k=3) -> list[dict]:
        # 对历史对话建立向量索引
        history = get_all_history(session_id)
        if len(history) <= top_k:
            return history
        
        # 向量检索相关历史片段
        query_embedding = embed(current_query)
        history_embeddings = [embed(t.user_query) for t in history]
        scores = cosine_similarity(query_embedding, history_embeddings)
        
        # 返回最相关的 N 轮
        return [history[i] for i in top_indices(scores, top_k)]
```

**收益**:
- ✅ 只传递相关历史，大幅节省 token
- ✅ 提升回答针对性
- ✅ 支持超长对话历史检索
- ✅ 避免无关历史干扰模型

**付出**:
- ❌ 需要额外向量索引（内存或 Chroma）
- ❌ 每次请求做向量检索（+50ms）
- ❌ 实现复杂度高
- ❌ 需要维护历史向量索引

**推荐指数**: ⭐⭐⭐（高级优化，复杂场景）

#### Step 2: 新建 ConversationTurnRepository

```python
# app/db/repositories/conversation_turn_repo.py
class ConversationTurnRepository:
    def __init__(self, db: Session):
        self.db = db
    
    def get_turns(self, session_id: str, limit: int = 10) -> list[ConversationTurn]:
        return self.db.scalars(
            select(ConversationTurn)
            .where(ConversationTurn.session_id == session_id)
            .order_by(ConversationTurn.turn_index.desc())
            .limit(limit)
        ).all()
    
    def add_turn(self, turn: ConversationTurn) -> ConversationTurn:
        self.db.add(turn)
        self.db.flush()
        return turn
    
    def count_turns(self, session_id: str) -> int:
        return self.db.scalar(
            select(func.count(ConversationTurn.id))
            .where(ConversationTurn.session_id == session_id)
        ) or 0
    
    def clear_turns(self, session_id: str) -> None:
        self.db.execute(
            delete(ConversationTurn).where(ConversationTurn.session_id == session_id)
        )
```

#### Step 3: 修改 ConversationService

```python
# app/services/conversation_service.py
class ConversationService:
    def __init__(self, session_factory, max_history_turns=6):
        self.session_factory = session_factory
        self.max_history_turns = max_history_turns
    
    def get_history(self, session_id: str) -> list[dict]:
        with self.session_factory() as db:
            repo = ConversationTurnRepository(db)
            turns = repo.get_turns(session_id, limit=self.max_history_turns)
            
            # 按时间顺序排列（正序）
            turns = sorted(turns, key=lambda t: t.turn_index)
            
            # 格式化为历史文本
            history = []
            for t in turns:
                history.append(f"Q: {t.user_query}")
                history.append(f"A: {t.bot_reply[:200]}...")  # 截断过长回复
            return history
    
    def append_turn(
        self,
        session_id: str,
        user_query: str,
        bot_reply: str,
        intent: str = None,
        province_code: str = None,
        latency_ms: int = None,
    ):
        with self.session_factory() as db:
            turn_repo = ConversationTurnRepository(db)
            state_repo = ConversationRepository(db)
            
            # 获取轮次序号
            turn_index = turn_repo.count_turns(session_id) + 1
            
            # 存储完整对话轮次
            turn = ConversationTurn(
                session_id=session_id,
                turn_index=turn_index,
                user_query=user_query,
                bot_reply=bot_reply,
                intent=intent,
                province_code=province_code,
                latency_ms=latency_ms,
            )
            turn_repo.add_turn(turn)
            
            # 更新会话状态（保留最新槽位）
            state = state_repo.get(session_id)
            if state is None:
                state = ConversationState(session_id=session_id)
            if province_code:
                state.province_code = province_code
            state.last_question = user_query
            state.last_intent = intent
            state.updated_at = datetime.utcnow()
            state_repo.upsert(state)
            
            db.commit()
    
    def clear_history(self, session_id: str):
        with self.session_factory() as db:
            turn_repo = ConversationTurnRepository(db)
            turn_repo.clear_turns(session_id)
            db.commit()
```

```python
def _cleanup(self):
    with SessionLocal() as db:
        # 清理过期会话状态
        state_repo = ConversationRepository(db)
        state_repo.clear_expired(self.ttl_minutes)
        
        # 清理过期对话轮次（关联删除或单独清理）

        db.commit()
```

## 流式输出说明

**什么是流式输出？**

流式输出（Streaming）是指 LLM 生成回答时，逐步返回内容而不是等待全部生成完毕再一次性返回。例如：

```python
# 非流式（一次性返回）
response = llm.invoke("陕西规则是什么")
return {"answer": response}  # 用户等待 5-10 秒后一次性看到全部内容

# 流式（逐步返回）
for chunk in llm.stream("陕西规则是什么"):
    yield {"chunk": chunk}  # 用户实时看到内容逐步出现
```

**与记忆管理的关系**：
- 流式输出不影响历史存储逻辑
- 存储时仍保存完整的 `bot_reply`（流式结束后拼接）
- 对公司内部服务器场景，流式输出可以提升用户体验（减少等待感）

**公司内部服务器建议**：
- 可以启用流式输出，无需额外依赖
- FastAPI 原生支持 `StreamingResponse`
- 存储逻辑不变：流式结束后，将拼接的完整回复存入 `ConversationTurn`
