# 飞书机器人并发处理优化 - 线程池方案

## 目标

使用线程池处理并发请求，避免 LLM 调用阻塞主线程，支持多用户同时提问。

## 修改文件

- `app/feishu_bot.py` - 添加线程池管理
- `app/langchain/llm.py` - 修复 MiniMaxLLMWrapper 竞态条件

## 实施步骤

### 1. 修复 MiniMaxLLMWrapper 竞态条件

**文件**: `app/langchain/llm.py`

在 `_get_client()` 方法中添加线程锁，防止多线程同时创建 client。

```python
# 添加到类属性
import threading

class MiniMaxLLMWrapper:
    def __init__(self, ...):
        ...
        self._lock = threading.Lock()

    def _get_client(self) -> ChatAnthropic:
        if self._client is None:
            with self._lock:
                if self._client is None:  # double-check
                    self._client = create_minimax_llm(...)
        return self._client
```

### 2. 在 FeishuBot 添加线程池

**文件**: `app/feishu_bot.py`

使用 `concurrent.futures.ThreadPoolExecutor` 处理消息：

```python
from concurrent.futures import ThreadPoolExecutor

class FeishuBot:
    def __init__(self):
        ...
        self.executor = ThreadPoolExecutor(max_workers=10, thread_name_prefix="feishu-handler")

    def _handle_message(self, data: lark.im.v1.P2ImMessageReceiveV1) -> None:
        if self.service:
            self.executor.submit(self.service.handle_message, data)

    def stop(self) -> None:
        self.executor.shutdown(wait=True, cancel_futures=False)
        logger.info("Feishu bot stopped")
```

### 3. 配置参数

考虑将线程池大小配置化：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `FEISHU_MAX_WORKERS` | 10 | 最大并发处理数 |

可在 `app/config.py` 添加配置项。

## 修改前后对比

**修改前** (同步阻塞):
```
用户A发消息 -> LLM调用(10秒) -> 回复A
用户B发消息 (在A处理期间) -> 等待... -> LLM调用(10秒) -> 回复B
总耗时: 20秒
```

**修改后** (线程池):
```
用户A发消息 -> 线程1: LLM调用(10秒) -> 回复A
用户B发消息 -> 线程2: LLM调用(10秒) -> 回复B
总耗时: 10秒 (并行)
```

## 注意事项

1. **线程安全已保证**: 
   - DB session 每次调用创建新的 (已确认安全)
   - `_check_and_mark` 已有锁保护
   - MiniMaxLLMWrapper 将加锁

2. **资源限制**:
   - 线程池大小 10 适合中小规模并发
   - 可根据服务器配置调整

3. **优雅关闭**:
   - `stop()` 方法调用 `executor.shutdown()` 等待任务完成
