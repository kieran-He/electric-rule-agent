# RAGAS 评估支持计划

## 目标

实现回复效果评估功能，能够：
1. 自动保存 RAGAS 评估所需的数据（contexts 文本）
2. 定期执行 RAGAS 评估
3. 通过 API 查看评估指标（faithfulness、answer_relevancy、context_precision）

---

## 问题分析

### 当前保存的数据

| 数据类型 | 保存位置 | RAGAS 需要 | 状态 |
|----------|----------|------------|------|
| question | TraceRecord.raw_query / ConversationTurn.user_query | ✅ | 已保存 |
| answer | ConversationTurn.bot_reply | ✅ | 已保存 |
| contexts 文本 | 无 | ✅ | **缺失** |
| faithfulness | EvaluationRecord.llm_faithfulness_score | ✅ | 有字段但无数据 |
| answer_relevancy | EvaluationRecord.llm_answer_relevancy_score | ✅ | 有字段但无数据 |
| context_precision | EvaluationRecord.llm_context_precision_score | ✅ | 有字段但无数据 |

### 缺失的关键问题

1. **TraceRecord 缺少 contexts 文本字段** - 只有 doc_ids，无文档内容
2. **orchestrator_hybrid.py save_trace 不保存 contexts** - 需要添加
3. **无自动 RAGAS 评估机制** - EvaluationRecord 有字段但从未填充
4. **无评估指标查看 API** - metrics API 不包含 RAGAS 指标

## 实现方案

### 1. 修改 TraceRecord 模型

**文件**: `app/db/models/trace_record.py`

新增字段：
```python
retrieved_doc_texts: Mapped[str | None] = mapped_column(Text, nullable=True)  # JSON 数组
answer_text: Mapped[str | None] = mapped_column(Text, nullable=True)  # 生成的答案
```

### 2. 修改 TraceService

**文件**: `app/services/trace_service.py`

- `save_trace()` 添加 `retrieved_doc_texts` 和 `answer_text` 参数
- `get_trace()` 返回 contexts 文本

### 3. 修改 orchestrator_hybrid.py

**文件**: `app/langchain/orchestrator_hybrid.py`

在 `save_trace()` 调用时添加：
```python
retrieved_doc_texts=[c.text[:500] for c in chunks],  # 截取前500字符避免过长
answer_text=answer,
```

### 4. 新建 EvaluationService

**文件**: `app/services/evaluation_service.py`

功能：
- 从 TraceRecord/ConversationTurn 获取评估数据
- 调用 RagasEvaluator 执行评估
- 将评估结果保存到 EvaluationRecord

### 5. 新建评估 API 路由

**文件**: `app/api/routes_evaluation.py`

端点：
- `GET /evaluation/recent` - 获取最近的评估记录
- `GET /evaluation/summary` - 获取评估指标汇总（平均 faithfulness 等）
- `POST /evaluation/run` - 手动触发评估（可选）

### 6. 修改 routes_metrics.py

**文件**: `app/api/routes_metrics.py`

新增端点：
- `GET /metrics/ragas` - 获取 RAGAS 指标汇总

## 评估触发时机

有两种方案可选：

### 方案 A：每次查询后自动评估（实时）
- 优点：及时获取评估数据
- 缺点：增加响应延迟（约 2-5 秒）

### 方案 B：定期批量评估（离线）
- 优点：不影响查询响应时间
- 缺点：评估数据有延迟

**建议**：方案 B（定期批量评估），通过定时任务或手动 API 触发

## API 设计

### GET /evaluation/recent
返回最近的评估记录列表：
```json
{
  "records": [
    {
      "trace_id": "trace_xxx",
      "question": "...",
      "answer": "...",
      "faithfulness": 0.85,
      "answer_relevancy": 0.90,
      "context_precision": 0.80,
      "created_at": "2026-04-28T..."
    }
  ]
}
```

### GET /evaluation/summary
返回指标汇总：
```json
{
  "total_records": 100,
  "avg_faithfulness": 0.85,
  "avg_answer_relevancy": 0.90,
  "avg_context_precision": 0.80,
  "period_hours": 24
}
```

### GET /metrics/ragas
返回 RAGAS 指标趋势：
```json
{
  "hourly": [
    {"hour": "14:00", "faithfulness": 0.85, "answer_relevancy": 0.90},
    {"hour": "15:00", "faithfulness": 0.82, "answer_relevancy": 0.88}
  ],
  "daily_avg": {
    "faithfulness": 0.83,
    "answer_relevancy": 0.89
  }
}
```
