# RAG系统评价指标设计方案

## 一、目标
为陕西电力市场规则智能问答系统设立一套完整的评价指标，用于评估每次改动后系统输出质量的变化，支持A/B对比和持续优化。

---

## 二、评价指标体系设计

### 2.1 检索级指标（Retrieval Metrics）
评估检索环节的有效性，数据来源：TraceRecord

| 指标 | 计算方式 | 目标阈值 | 数据来源 |
|------|----------|----------|----------|
| recall@k | Top-k召回文档中命中正确文档的比例 | ≥85% | benchmark测试集 |
| precision@k | Top-k召回文档中相关文档比例 | ≥80% | benchmark测试集 |
| hit_rate | 是否命中至少一个正确主题文档 | ≥90% | TraceRecord.retrieved_doc_ids |
| avg_score | 向量相似度平均值 | ≥0.7 | TraceRecord.rerank_scores |
| OOD_rate | "查不到任何有意义文档"的比例 | ≤10% | 低分样本统计 |

### 2.2 答案质量指标（Answer Quality）
评估LLM输出质量

| 指标 | 计算方式 | 目标阈值 | 数据来源 |
|------|----------|----------|----------|
| citation_rate | 回答带来源的比例 | ≥95% | QueryAnswer.citations非空判定 |
| citation_accuracy | 条号/标题路径正确率 | ≥90% | 人工标注benchmark |
| formal_doc_priority | 正式文件优先命中率 | ≥95% | CitationItem.status判断 |
| draft_misuse_rate | 征求意见稿误答率 | ≤5% | status='draft'的回答比例 |
| faithfulness | 回答是否忠实引用文档 | ≥85% | Ragas评估 |
| answer_relevancy | 是否回答了用户问题 | ≥85% | Ragas评估 |
| context_precision | 检索文档与问题相关性 | ≥80% | Ragas评估 |

### 2.3 流程与多轮指标（Flow & Context）

| 指标 | 计算方式 | 目标阈值 | 数据来源 |
|------|----------|----------|----------|
| flow_complete_rate | 流程问答完整率(覆盖所有步骤) | ≥85% | 流程类问题benchmark |
| context_continuation_rate | 多轮上下文延续正确率 | ≥80% | 多轮对话benchmark |
| rejection_correct_rate | 拒答正确率(该拒答时拒答) | ≥85% | OOD类问题benchmark |

### 2.4 性能指标（Performance）

| 指标 | 计算方式 | 目标阈值 | 数据来源 |
|------|----------|----------|----------|
| avg_latency_ms | 平均响应时间 | ≤8000ms | TraceRecord.latency_ms |
| p99_latency_ms | 99分位响应时间 | ≤15000ms | 统计计算 |
| throughput_qps | 每秒查询数 | ≥10 | 压测数据 |

## 三、基准测试集设计

### 3.1 测试集构成（共100条）
```
条款问答 40条  - 基于知识库文档生成，覆盖中长期、现货、零售、结算、计量等规则
流程问答 20条  - 基于知识库文档生成，储能参与市场、虚拟电厂注册、售电公司准入等
对比问答 15条  - 部分基于文档（主体准入对比），部分虚构跨省场景（省间规则对比）
结算问答 15条  - 基于知识库文档生成，日清月结、结算周期、计量要求
拒答题   10条  - 自主生成知识库外问题（其他省份规则、通用知识、超范围问题）
```

**生成方式说明**：
- **条款/流程/结算问答**（75条）：基于data/docs/SN目录文档自动生成，可追溯expected_docs
- **对比问答**（15条）：10条基于文档（主体准入条件对比），5条虚构跨省对比场景（测试多省检索）
- **拒答问答**（10条）：自主生成知识库外问题：
  - 3条其他省份规则（广东、山东中长期交易）
  - 3条通用电力知识（不在陕西规则中的行业知识）
  - 2条版本不明确问题（仅征求意见稿，应拒答或降级）
  - 2条超范围问题（政策预测、市场分析、投资建议）

### 3.2 每条测试数据格式
```json
{
  "question_id": "q001",
  "question": "陕西2026年中长期签约比例要求是什么？",
  "category": "clause_qa",
  "expected_docs": ["陕西省2026年电力市场化交易实施方案"],
  "expected_articles": ["二、总体要求"],
  "expected_answer_keywords": ["年度签约比例", "45%", "月度签约比例"],
  "should_reject": false,
  "expected_intent": "clause_qa"
}
```

### 3.3 Benchmark自动生成方案
使用LLM基于知识库文档自动生成测试问题：

```python

        4. 保存为benchmark.json
        """
        
    def generate_clause_questions(self, doc: Document) -> List[str]:
        """生成条款类问题（微观/宏观、长/短）"""
        # 模板："{主体}{年份}{规则类型}要求是什么？"
        # 模板："{市场类型}的{具体规则}如何执行？"
        
    def generate_flow_questions(self, doc: Document) -> List[str]:
        """生成流程类问题"""
        # 模板："{主体}参与{市场类型}的完整流程是什么？"
        
    def generate_compare_questions(self) -> List[str]:
        """生成对比类问题（跨省/跨主体）"""
        
    def generate_rejection_questions(self) -> List[str]:
        """生成应拒答类问题（知识库外内容）"""
```

### 3.4 问题多样性要求
- **长短分布**：短问题(≤15字) 30%、中等问题(15-30字) 50%、长问题(>30字) 20%
- **宏观微观**：宏观总结类 20%、微观条款类 60%、跨文档综合类 20%
- **场景覆盖**：
  - 主体：发电企业、售电公司、电力用户、虚拟电厂、独立储能
  - 市场：中长期、现货、零售、结算、计量、辅助服务
  - 时间：年度、月度、日前、实时、日内

### 4.4 Ragas评估集成
```python
# evaluation/ragas_evaluator.py

from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy, context_precision
from datasets import Dataset

class RagasEvaluator:
    """使用Ragas进行LLM质量评估"""
    
    def evaluate_batch(
        self, 
        questions: List[str],
        answers: List[str],
        contexts: List[List[str]],  # 检索到的文档片段
        ground_truths: Optional[List[str]] = None
    ) -> Dict[str, float]:
        """
        返回ragas评估结果：
        - faithfulness: 回答是否基于检索文档
        - answer_relevancy: 回答与问题相关性
        - context_precision: 检索文档与问题相关性
        """
        dataset = Dataset.from_dict({
            "question": questions,
            "answer": answers,
            "contexts": contexts,
            "ground_truth": ground_truths or [""] * len(questions)
        })
        result = evaluate(
            dataset,
            metrics=[faithfulness, answer_relevancy, context_precision]
        )
        return {
            "faithfulness": result["faithfulness"],
            "answer_relevancy": result["answer_relevancy"],
            "context_precision": result["context_precision"]
        }
```

### 11.7 元数据深度检查与问题识别

#### 问题1: 字段命名不一致

**Processed JSON字段 → ChromaDB期望字段映射**：

| Processed JSON字段 | ChromaDB期望字段 | 问题 |
|-------------------|----------------|------|
| source_file (完整路径) | source_name (仅文件名) | ❌ 需提取basename |
| origin_doc_id | file_hash | ✅ 匹配 |
| - | doc_id | ❌ **缺失**，需生成 "{file_hash}:{idx}" |
| - | source_path | ❌ **缺失**，需从source_file提取 |
| doc_name | doc_title | ❌ 需去掉前缀("转载丨"、"附件") |

```python
# 1. 字段映射函数
def map_clause_to_chroma_metadata(clause: dict, metadata: dict, idx: int) -> dict:
    """
    从processed JSON clause映射到ChromaDB metadata
    
    解决问题1、2、3的所有字段映射
    """
    file_hash = metadata["file_hash"]
    source_file = clause["source_file"]
    source_name = Path(source_file).name  # 提取basename
    source_path = str(Path(source_file).resolve())  # 完整路径
    doc_title = clean_doc_title(metadata["doc_name"])  # 去掉前缀
    effective_date = parse_effective_date(metadata.get("effective_date"))  # 解析日期
    
    return {
        "province_code": clause["province_code"],
        "file_hash": file_hash,
        "doc_id": f"{file_hash}:{idx}",  # 生成唯一id
        "source_name": source_name,
        "source_path": source_path,
        "doc_title": doc_title,
        "effective_date": effective_date or "",
        "policy_level": extract_policy_level(clause["clause_text"]),  # 从内容提取
    }

# 2. 清理doc_title
def clean_doc_title(doc_name: str) -> str:
    """
    去掉"转载丨"、"附件"、"关于印发"等前缀
    
    示例：
    "转载丨陕西省发展和改革委员会关于印发..." → "陕西省..."
    "附件1陕西电力现货市场..." → "陕西电力现货市场..."
    """
    prefixes = ["转载丨", "附件", "关于印发《", "陕西省发展和改革委员会"]
    title = doc_name
    for prefix in prefixes:
        if title.startswith(prefix):
            title = title[len(prefix):]
    return title.strip()

# 3. 解析effective_date
def parse_effective_date(date_str: str | None) -> str:
    """
    解析日期字符串为YYYY-MM-DD格式
    
    处理null值、多种格式（2025年12月7日、2025-12-07等）
    """
    if not date_str:
        return ""
    
    # 尝试多种格式解析
    patterns = [
        r"(20\d{2})年(\d{1,2})月(\d{1,2})日",  # 2025年12月7日
        r"(20\d{2})-(\d{1,2})-(\d{1,2})",      # 2025-12-07
    ]
    
    import re
    for pattern in patterns:
        match = re.search(pattern, date_str)
        if match:
            year, month, day = match.groups()
            return f"{year}-{month.zfill(2)}-{day.zfill(2)}"
    
    return ""

# 4. 提取policy_level
def extract_policy_level(clause_text: str) -> str:
    """
    从clause_text前800字符判断政策级别
    
    规则：
    - 包含"国家发展改革委" → "national"
    - 包含"省"或"自治区" → "province"
    - 默认 → "unknown"
    """
    sample = clause_text[:800]
    if any(k in sample for k in ["国家发展改革委", "国家能源局", "中华人民共和国"]):
        return "national"
    if "省" in sample or "自治区" in sample:
        return "province"
    return "unknown"

# 5. 映射Document表字段
def map_metadata_to_document(metadata: dict) -> dict:
    """
    从processed JSON metadata映射到SQL Document表
    
    解决问题2的所有字段映射和类型转换
    """
    return {
        "province_code": metadata["province_code"],
        "doc_name": metadata["doc_name"],
        "doc_type": metadata.get("doc_type", "notice"),
        "market_type": metadata.get("market_type"),
        "subject_scope": json.dumps(metadata.get("subject_scope", [])),  # 序列化[]
        "version_name": metadata.get("version_name"),
        "status": metadata.get("status", "formal"),
        "issue_date": parse_date_object(metadata.get("issue_date")),  # null→None
        "effective_date": parse_date_object(metadata.get("effective_date")),
        "source_file": metadata["source_file"],
        "file_hash": metadata["file_hash"],
        "is_current": metadata.get("is_current", True),
        "parent_doc_id": None,  # null→None
        "raw_text": None,  # 暂不导入，节省空间
    }

# 6. 解析date对象
def parse_date_object(date_str: str | None) -> date | None:
    """
    将字符串/null转换为datetime.date对象
    
    处理null→None，字符串→date对象
    """
    if not date_str:
        return None
    
    parsed_str = parse_effective_date(date_str)
    if not parsed_str:
        return None
    
    from datetime import datetime
    return datetime.strptime(parsed_str, "%Y-%m-%d").date()

# 7. 导入流程主逻辑
def import_processed_json(json_path: str, repository, db_session):
    """
    完整导入流程：
    
    1. 加载processed JSON
    2. 创建Document记录
    3. 遍历clauses：
       - 映射metadata → ChromaDB metadata
       - 插入Clause表（关联Document.id）
       - 批量调用repository.ingest_chunks
    4. 返回统计
    """
    with open(json_path) as f:
        data = json.load(f)
    
    # 创建Document
    doc_data = map_metadata_to_document(data["metadata"])
    document = Document(**doc_data)
    db_session.add(document)
    db_session.flush()  # 获取document.id
    
    # 准备ChromaDB导入
    texts = []
    metadatas = []
    
    for idx, clause in enumerate(data["clauses"]):
        # 映射metadata
        chroma_meta = map_clause_to_chroma_metadata(
            clause, data["metadata"], idx
        )
        
        # 添加到批量导入
        texts.append(clause["clause_text"])
        metadatas.append(chroma_meta)
        
        # 创建Clause记录（可选）
        # clause_record = Clause(
        #     doc_id=document.id,
        #     chapter_no=clause.get("chapter_no"),
        #     ...
        # )
        # db_session.add(clause_record)
    
    # 导入ChromaDB
    chunk_count = repository.ingest_chunks(
        texts=texts,
        metadatas=metadatas,
        kb_scope="province",
        province_code=data["metadata"]["province_code"],
        rebuild=False,
    )
    
    db_session.commit()
    
    return {
        "doc_name": document.doc_name,
        "clauses_imported": chunk_count,
        "file_hash": document.file_hash,
    }
```

**关键设计决策**：

1. **subject_scope序列化**：[] → "[]" (JSON string)
2. **日期null处理**：null → None (允许SQL nullable)
3. **policy_level提取**：从clause_text内容动态提取（因processed JSON无此字段）
4. **doc_id生成**："{file_hash}:{idx}" 格式（满足ChromaDB期望）
5. **source_name提取**：Path(source_file).name（去掉路径）
6. **doc_title清理**：去掉"转载丨"、"附件"等前缀
7. **rule_tags忽略**：暂不导入RuleTag表（简化实现）

### 11.10 风险点与应对策略

**风险1: policy_level提取不准确**

- 影响：ChromaDB metadata错误，但不影响检索

- 影响：ChromaDB metadata为空字符串
- 应对：允许空值，检索时无需过滤日期

**风险3: ChromaDB embedding失败**

- 问题：deterministic embedder质量差
- 影响：检索召回率低
- 应对：先用deterministic测试，后续可升级sentence_transformers

**风险4: SQL插入失败**

- 问题：字段类型不匹配或约束冲突
- 影响：导入中断
- 应对：使用try-catch包裹每条记录插入，记录失败原因

- 问题：11个文档，约500条clauses，批量导入可能慢
- 影响：导入时间超过预期
- 应对：按文档分批导入，每批100条clauses

```python
        "file_hash": doc_title,  # 使用标题
        "province_code": clause["province_code"],
        "source_name": clause["doc_name"],
        "doc_id": f"{doc_title}:{idx}",
        "doc_type": clause.get("doc_type", ""),
        "status": clause.get("doc_status", ""),
        "market_type": clause.get("doc_market_type", ""),
        "chapter_no": clause.get("chapter_no") or "",
        "section_no": clause.get("section_no") or "",
        "article_no": clause.get("article_no") or "",
        "title_path": clause.get("title_path", ""),
        "clause_text": clause["clause_text"],
    }

if __name__ == "__main__":
    main()
```
