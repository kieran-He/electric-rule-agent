# Baseline vs Hybrid 全流程对比实验计划

## 实验目标

在100条陕西省专用数据集上，对比 Baseline (Vector-only) 与 Hybrid (Vector+BM25+Rerank) 的全流程RAG效果，包括：
- 检索质量指标
- LLM生成答案
- Ragas评估指标
- 最终答案记录

---

### 2. 数据集生成

**来源**: `scripts/generate_benchmark_sn.py`

**数据分布**:
| 类别 | 数量 | 说明 |
|------|------|------|
| clause_qa | 50 | 陕西政策条款查询 |
| flow_qa | 20 | 陕西准入流程 |
| settlement_qa | 20 | 陕西结算规则 |
| rejection | 10 | 知识库外问题 |
| **总计** | **100** | |

**注意**: 不包含 compare_qa（仅单省文档）

### 3. 全流程评估步骤

#### Phase 1: 初始化
- Vector Repository (ChromaDB)
- BM25 Indexer (k1=1.5, b=0.6)
- BGE Reranker (bge-reranker-base)
- LLM Orchestrator (LangChainQAOrchestrator)
- Ragas Evaluator (MiniMax API)
- Province Detector (动态省份检测)

#### Phase 2: Baseline评估
- Vector-only检索 (top_k=12)
- LLM生成答案
- 记录：检索时间、生成时间、答案内容、检索文档

#### Phase 3: Hybrid评估
- Vector + BM25 + Rerank检索
- 省份支持检查（动态检测）
- LLM生成答案
- 记录：检索时间、生成时间、答案内容、检索文档

#### Phase 4: Ragas评估
- faithfulness (答案对上下文忠实度)
- answer_relevancy (答案与问题相关性)
- context_precision (上下文精确度)

#### Phase 5: 检索指标计算
- recall@3, recall@5
- precision@k
- hit_rate (关键词匹配优化版)
- avg_score (校准后)
- rejection_accuracy

#### Phase 6: 生成报告
- JSON报告（详细结果）
- MD报告（可视化总结）

## 风险评估

### 1. LLM生成延迟
- 每问题约3-5秒生成时间
- 100条问题约需15-20分钟生成阶段
- **缓解**: 批量处理、异步生成

### 2. Ragas评估延迟
- Ragas需要调用LLM评估
- 100条问题约需额外20-30分钟
- **缓解**: 可选择跳过Ragas或减少样本

### 3. Reranker延迟
- Hybrid检索每问题约8秒
- 100条问题约需15分钟检索
- **缓解**: 已预加载模型，减少首次延迟

### 4. 总实验时间预估
- Phase 1 初始化: 10秒
- Phase 2 Baseline检索+生成: ~10分钟
- Phase 3 Hybrid检索+生成: ~20分钟
- Phase 4 Ragas评估: ~25分钟
- Phase 5-6 报告生成: 1分钟
- **总计**: 约 **55-60分钟**

---

## 决策点

### 决策1: 是否包含Ragas评估？
Ragas评估会增加约25分钟延迟。

**选项**:
- A. 包含Ragas（完整评估，~60分钟）
- B. 跳过Ragas（仅检索+生成，~35分钟）

### 册策2: 数据集规模确认
- 当前generate_benchmark_sn.py生成100条
- 是否需要更多样本？
